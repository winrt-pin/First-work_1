Git & GitHub

The Stuck Beginner's Guide

Stuck on Git? You're not alone. This page covers the only 6 commands you actually need to start.

1. Get a copy of a repo

git clone https://github.com/user/repo.git

Downloads the project to your computer.

2. See what changed

git status

Shows which files you've edited, added, or deleted.

3. Save your changes (the 3-step ritual)

git add .
git commit -m "describe what you changed"
git push

add = pick what to save · commit = save it · push = send to GitHub.

4. Get other people's changes

git pull

5. Work on something new without breaking main

git checkout -b my-new-thing

Creates a branch — a safe sandbox. Mess up? Just delete the branch.

Stuck tip: 90% of Git problems are fixed by running git status first. It usually tells you exactly what to do next.

Every Git command and concept explained in plain English.

Core concepts

TermWhat it means
repoShort for "repository" — your project folder tracked by Git.
commitA saved snapshot of your changes. Each one has a unique ID (hash).
branchA separate timeline of commits. Lets you experiment without breaking main.
mainThe default branch — your project's "official" version.
originNickname for the remote repo on GitHub.
HEADA pointer to the commit you're currently on.
staging areaThe waiting room for changes before you commit them. git add puts files here.
remoteA version of your repo hosted somewhere else (usually GitHub).
mergeCombine the changes from one branch into another.
pull request (PR)A GitHub feature: propose your branch's changes to be merged.

Everyday commands

CommandWhat it does
git clone <url>Download a repo from GitHub to your computer.
git statusShow what's changed, staged, or untracked.
git add <file>Stage a file for the next commit.
git add .Stage everything that changed.
git commit -m "msg"Save staged changes with a message.
git pushSend local commits to GitHub.
git pullGet changes from GitHub into your local copy.
git logShow commit history.
git log --onelineCompact one-line-per-commit view.
git diffShow line-by-line what you've changed.

Branching commands

CommandWhat it does
git branchList your local branches.
git branch -rList remote branches.
git checkout <branch>Switch to an existing branch.
git checkout -b <name>Create a new branch and switch to it.
git switch <branch>Newer way to switch branches.
git merge <branch>Merge another branch into your current one.
git branch -d <name>Delete a local branch (safe — refuses if unmerged).
git push origin --delete <name>Delete a branch on GitHub.

Undo & rescue

CommandWhat it does
git restore <file>Throw away unstaged changes to a file.
git restore --staged <file>Unstage a file (undoes git add).
git revert <hash>Create a new commit that undoes a previous one. Safe for shared history.
git reset --hard <hash>⚠️ Wipe local changes back to a commit. Destructive — use with care.
git stashTemporarily shelve uncommitted changes so you can switch branches.
git stash popBring stashed changes back.

Setup & config

CommandWhat it does

.gitignoreA file listing things Git should never track (secrets, build files).

Real scenarios — what you type, what Git shows, and what actually changes.

git clone

Scenario: You want to download an existing repo to your computer.

You run:
git clone https://github.com/winrt-pin/First-work_1.git
You see:
Cloning into 'First-work_1'... remote: Enumerating objects: 3, done. remote: Counting objects: 100% (3/3), done. Receiving objects: 100% (3/3), done.
Effect: A new folder First-work_1 appears with all the project files and full Git history.

git status

Scenario: You edited a file and want to see what Git knows.

You run:
git status
You see:
On branch main Changes not staged for commit: modified: README.md Untracked files: notes.md
Effect: Nothing changes. This command only reads — it tells you what's edited (red) and what's new but untracked.

git add .

Scenario: You're ready to save your changes — first you have to "stage" them.

You run:
git add .
Then run git status and you see:
Changes to be committed: modified: README.md new file: notes.md
Effect: Files moved from "modified" (red) to "staged" (green). They're queued up — but not saved yet.

git commit -m

Scenario: Save your staged changes as a snapshot in history.

You run:
git commit -m "add notes file and update readme"
You see:
[main 7a3b1c2] add notes file and update readme 2 files changed, 12 insertions(+) create mode 100644 notes.md
Effect: A new commit (7a3b1c2) is added to your local history. Still local — GitHub doesn't know yet.

git push

Scenario: Send your commits to GitHub so they're backed up and visible online.

You run:
git push
You see:
Enumerating objects: 5, done. Writing objects: 100% (3/3), 412 bytes To https://github.com/winrt-pin/First-work_1.git dbb061a..7a3b1c2 main -> main
Effect: Your local commits are uploaded. Refresh GitHub and you'll see them in the repo.

git pull

Scenario: Someone else (or you on another computer) pushed changes — you want them.

You run:
git pull
You see:
Updating 7a3b1c2..f9c4d11 Fast-forward README.md | 3 +++ 1 file changed, 3 insertions(+)
Effect: Your local files update with the new changes from GitHub.

git checkout -b

Scenario: You want to try something risky without breaking main.

You run:
git checkout -b add-dark-mode
You see:
Switched to a new branch 'add-dark-mode'
Effect: A new branch is created from your current spot. Any new commits go on this branch — main stays untouched.

git merge

Scenario: Your branch is ready — bring its changes into main.

You run:
git checkout main
git merge add-dark-mode
You see:
Updating f9c4d11..b2e8a04 Fast-forward style.css | 8 ++++++++ 1 file changed, 8 insertions(+)
Effect: The branch's commits are now part of main's history. The branch label still exists until you delete it.

git log --oneline

Scenario: See your project's commit history at a glance.

You run:
git log --oneline
You see:
b2e8a04 add dark mode styles f9c4d11 update readme 7a3b1c2 add notes file dbb061a first commit
Effect: Read-only — shows you the timeline. Each line: short hash + commit message.

git diff

Scenario: You edited a file but forgot what you changed.

You run:
git diff
You see:
diff --git a/README.md b/README.md @@ -1,3 +1,4 @@ # Test_1Time My first GitHub repo +Now learning branches!
Effect: Read-only. Green lines = added, red lines = removed.

git restore

Scenario: You messed up a file — want to throw away your changes.

You run:
git restore README.md
You see:
(no output — silent success)
Effect: ⚠️ Your unsaved edits to README.md are gone forever. The file goes back to its last committed state.

git branch -d

Scenario: You merged a branch — time to clean it up.

You run:
git branch -d add-dark-mode
You see:
Deleted branch add-dark-mode (was b2e8a04).
Effect: The branch label is gone. The commits stay (they're now part of main's history).
